1proton-syncd desktop UI — first pass: notes, main window IA, status metaphors, tray, onboarding, plan review, conflicts, settings, file-manager emblems
1aDesign notes & assumptions — read first
Proton Drive Sync — Linux desktop UI
front end for proton-syncd · osirison/proton-drive-sync-engine
What I built from

There is no GUI in the repo, so nothing to recreate pixel-perfectly. The recreation baseline is the engine's real control surface, which I read: src/ipc.rs (ControlResponse, StatusHistoryEntry), src/daemon.rs (status strings, message copy, plan execution, locks), src/bin/proton-sync.rs, examples/proton-sync.toml, and the README. Every number, label and status string in these mocks maps to a real field.

Assumptions
  • The GUI is a thin client over the Unix socket at $XDG_RUNTIME_DIR/proton-sync.sock. It only ever sends status, pause, resume, syncnow — no new IPC verbs are invented for v1.
  • Anything the socket can't answer is read from disk: the TOML config, .sync/sync_index.db, .status.json, .metrics.json, and journalctl --user -u proton-syncd.
  • Dry-run review shells the daemon with --dry-run and renders the JSON plan. Conflict resolution is plain file operations on .proton-cloud sidecars — no engine change needed.
  • One folder pair in v1, but the sidebar and header already carry a pair selector so multi-pair fits later without a re-layout.
  • Ships as Flatpak (Fedora/Ubuntu/Arch), plus RPM/deb/AUR wrapping the same binaries + systemd user unit. Systemd status is surfaced in-app so an unloaded unit is not silent.

Identity
Repo hexagon: orange #E55B2B→#F59E0B = local/upload, cyan #06B6D4→#3B82F6 = remote/download. Direction is a colour, everywhere.
Type
IBM Plex Sans for UI, IBM Plex Mono for every path, glob, ID and count.
Danger
Red #EF4444 reserved for destructive_actions, local deletes and purges. Never decorative.
Density
Prosumer: counters use the engine's own field names on hover; nothing is rounded away.
